# Hot-load: put Claude-chan on any web page

The `hotload/` folder holds ready-built, self-contained scripts. A page needs no build step, no framework and no
change to its own code: one script tag (or a bookmark, or a userscript) adds the mascot, and `claudeChan.unload()`
takes her off again.

| File | What it is | Size |
|---|---|---|
| `hotload/loader.js` | The loader (IIFE). Loads the sprites from `<BASE>/assets/chars/`. | ~50 KB |
| `hotload/claude-chan.inline.js` | The same loader with all 21 sprites embedded as `data:` URIs. Needs no network. | ~2.3 MB |
| `hotload/claude-chan.user.js` | Userscript (Tampermonkey / Violentmonkey) that runs `loader.js`. | ~50 KB |
| `hotload/claude-chan.inline.user.js` | Userscript with the inline build, for sites with a strict Content-Security-Policy. | ~2.3 MB |
| `hotload/bookmarklet.txt` | The bookmarklet as one `javascript:` line. | <1 KB |
| [`docs/install.html`](install.html) | A page with a draggable bookmarklet button and a base-URL field. | |

These files are generated by `npm run build:loader` (source: `src/loader.ts`, `scripts/build-loader.mjs`) and are
committed, so a CDN can serve them straight from the repository. `npm run check:loader` fails when they are stale
or over their size budget (loader 80 KB, inline build 3.5 MB).

## Where the files come from (`<BASE>`)

`<BASE>` is the URL of the repository root as served over http(s). There are two ways to get one.

- **Local server (works now):** run `npm run serve:loader` (add `-- --port 5179` to choose the port). It serves
  `hotload/`, `assets/` and `docs/` on `http://127.0.0.1:5179/` with CORS and the Private-Network-Access header.
  Pages on `https://` sites may load scripts from `http://127.0.0.1`, because browsers treat localhost as secure.
- **jsDelivr (only once the GitHub repository is public):**
  `https://cdn.jsdelivr.net/gh/Kmaj1st/claude-chan@main/`. Pin a tag or commit instead of `main` for a stable
  version, for example `@<tag>/` or `@<commit-sha>/`.

## 1. Console one-liner

Open the developer console (F12) on any page and paste this:

```js
document.head.append(Object.assign(document.createElement('script'),{src:'http://127.0.0.1:5179/hotload/loader.js'}))
```

Or, as a module import (it also works where `document.head` is missing):

```js
import('http://127.0.0.1:5179/hotload/loader.js')
```

Replace `http://127.0.0.1:5179/` with the jsDelivr base once the repository is public. Running either line twice
does nothing: there is never more than one mascot.

## 2. Bookmarklet

Open [`docs/install.html`](install.html), either from the local server at `http://127.0.0.1:5179/` or as a file,
and drag the **Claude-chan** button to the bookmarks bar. The base-URL field rewrites the bookmark. Clicking the
bookmark adds Claude-chan; clicking it again removes her. The code for the jsDelivr base is in
`hotload/bookmarklet.txt`.

## 3. Userscript

Install `hotload/claude-chan.user.js` in Tampermonkey or Violentmonkey: open its raw URL, or create a new script
and paste the file. It uses `@grant none`, `@noframes` and `@match *://*/*`. To limit it to some sites, edit the
`@match` lines, or rebuild with `USERSCRIPT_MATCH="https://example.com/*,https://*.example.org/*" npm run build:loader`.
The base baked into the userscript and the bookmarklet is jsDelivr `@main`; set `CLAUDE_CHAN_BASE=http://127.0.0.1:5179/`
when building to use the local server instead.

## Options

You can set options as `data-*` attributes on the loader's `<script>` tag, or as `window.claudeChanConfig` set
before the loader runs. `window.claudeChanConfig` wins when both are given.

```js
window.claudeChanConfig = {
  position: 'bottom-right', // home corner: bottom-left (default) | bottom-right | top-left | top-right
  dock: 'free',             // free (drag anywhere, default) | fixed-default
  size: 180,                // character height in px (default 220)
  zIndex: 2147483000,       // stacking order of the overlay
  renderer: 'auto',         // auto | sprite | procedural (Live2D is not part of the hot-load bundle)
  sprites: 'https://example.com/my-poses/', // another pose set (poses.json + motions.json + images)
  base: 'http://127.0.0.1:5179/',           // repository root; default: derived from the loader's own URL
  storageKey: 'claude-chan:position',       // false = do not remember the dragged spot
  consoleApi: 'claudeChan', // global name of the console API; false = none
  frames: false,            // true = also mount inside iframes (default: top frame only)
  hub: { token: '…', port: 8765 },          // connect to the local MCP hub (docs/MCP.md); off by default
  postMessage: false,       // true = same-origin postMessage bridge, or a list of allowed origins
};
```

The attribute names are `data-position`, `data-dock`, `data-size`, `data-z-index`, `data-renderer`,
`data-sprites`, `data-base` and `data-frames`. Never put the hub token in a URL or a shared bookmarklet.

## Console API

The hot-loaded mascot has the normal console commands (see [API.md](API.md)), plus two more:

| Command | Effect |
|---|---|
| `claudeChan.unload()` | Removes the mascot completely: DOM, event listeners, animation loop, hub/postMessage bridges and the globals. Loading again afterwards works. |
| `claudeChan.unload({ forget: true })` | Also deletes the remembered position and the persisted hide flag from `localStorage`. |
| `claudeChan.version` | The loader version. |

The full controller (`act`, `say`, `setMood`, `lookAt`, `on`, …) is at `window.__claudeChanLoader.controller`.

## How it behaves on other people's pages

- **Isolation from the page's CSS:** everything sits in a shadow root inside one `<claude-chan-loader>` element
  appended to `<html>`. That element carries inline `!important` styles, and where the browser supports the Popover
  API it is shown in the top layer. Global rules such as `* { transform; filter; display:none }`, `img { … }`, or a
  `filter` / `transform` on `<html>` (used by dark-mode extensions) therefore do not move, shrink, hide or tint her.
  Inherited fonts and colours do not reach the speech bubble.
- **Clicks:** only the character takes pointer events. The rest of the overlay lets clicks through to the page.
- **Single-page apps:** route changes (`pushState`) and frameworks that replace `<body>` do not touch the overlay.
  If something removes it from `<html>`, the same element is put back without a remount, so the position, mood and
  timers are kept.
- **iframes:** the loader only mounts in the top frame, unless you set `frames: true`.
- **Existing mascot:** if `window.claudeChan` already exists (for example, a page that embeds Claude-chan itself),
  the loader skips loading and logs a warning.
- **Sprites fail to load** (404, blocked images, offline): she falls back to the built-in drawn (SVG) puppet, and
  the page sees no errors.

## Sites that block it: Content-Security-Policy and mixed content

Some sites send a strict `Content-Security-Policy` header, for example `script-src 'self'`. The browser then refuses
the loader, and the console shows an error like:

```
Refused to load the script 'https://cdn.jsdelivr.net/…/hotload/loader.js' because it violates the following
Content Security Policy directive: "script-src 'self'".
```

The bookmarklet shows an alert in that case. Related limits:

- `img-src` without your base blocks the sprite images. She then shows the drawn puppet instead.
- `connect-src` blocks the local MCP hub WebSocket (`ws://127.0.0.1:8765`).
- Mixed content: an `https://` page cannot load `http://` scripts from any host other than localhost or 127.0.0.1.
  Use jsDelivr (https) or the local server on 127.0.0.1.

Fallbacks, from easiest to most robust:

1. **Userscript with the inline build** (`hotload/claude-chan.inline.user.js`). Userscript managers inject the
   script themselves, so the page's `script-src` does not apply. The sprites are embedded as `data:` URIs, so no
   network request is made. If the page's `img-src` also forbids `data:` images, she still appears as the drawn
   puppet. The automated tests check exactly this: the external loader is blocked on a strict-CSP page, and the
   inline build injected outside the page's script-src mounts with its embedded sprites.
2. **Developer console:** pasting the *contents* of `hotload/claude-chan.inline.js` into the console also works on
   most CSP pages, because console input is not subject to `script-src`.
3. **Browser extension:** an extension content script can run `claude-chan.inline.js` on any site. There is no
   packaged extension yet (see the [roadmap](ROADMAP.md)).

## Tests

`npm run test:loader` builds `hotload/` and then drives headless Chrome or Edge (`CHROME_PATH` to override). The
fixture pages are served from a different origin than the loader, like a third-party site. The test covers:

- a plain page: the one-liner, sprites from the loader origin, dragging, and click-through;
- double and triple load (still one mascot);
- `unload()` and `unload({ forget: true })` cleanup, then loading again;
- `import()` loading;
- `data-*` attributes and `window.claudeChanConfig`;
- a page with hostile global CSS (including `transform` / `filter` on `<html>`);
- an SPA with four kinds of route change, including rebuilding `<body>` and `<html>` children;
- iframes (off by default, on with `frames: true`);
- a strict-CSP page, where the external loader is blocked and the inline build works;
- CSP without `data:` images, where she falls back to the drawn puppet;
- the userscript body.
